# 第 10 章：迁移、发布与回滚——部署不是终点

> 本章目标：处理数据库迁移与部署的顺序（先测试迁移、expand-migrate-contract）；建立发布标识与回滚的完整流程；写一份可执行的回滚说明。
>
> 关键概念：迁移与部署顺序、expand-migrate-contract、部署回滚与发布标识。

---

## 10.1 最危险的部署：代码与 schema 不兼容

先认识两个词：**schema** 是数据库的表结构（有哪些表/列/约束）；**迁移（migration）** 是修改 schema 的脚本（加列/改类型等，阶段 8/9 详讲）。

```
12:00 部署新代码（依赖新列 priority）
12:01 迁移还没跑 → 所有查询报 column does not exist
12:05 跑迁移 → 恢复
```

或者反过来：

```
12:00 跑迁移（删了旧列 legacy_status）
12:01 旧代码还在跑（滚动部署：新旧实例交替上线中）→ 旧实例全部报错
```

两种事故的根源：**代码与 schema 的变更不是原子的**。解法不是「更快」，而是**让变更兼容**。

## 10.2 expand-migrate-contract：三步兼容法

以「给 task 加 priority 列并替换旧 status 语义」为例：

| 阶段         | 动作                                                   | 兼容性                   |
| ------------ | ------------------------------------------------------ | ------------------------ |
| **expand**   | 迁移只**加**新列（nullable/有默认值），不删不改旧列    | 旧代码无感，新代码可选用 |
| **migrate**  | 部署新代码（双写/回填）；后台任务回填历史数据          | 新旧代码都能跑           |
| **contract** | 确认无旧代码/旧查询后，下一次迁移才删旧列、加 NOT NULL | 收尾，不可与部署同批     |

原则：**任何一次部署，前后两个版本的代码都必须能跑在当前 schema 上**。删列、改名、加非空约束这类破坏性变更，永远滞后一个发布周期。

## 10.3 迁移在流水线里的位置

```
PR 门禁：迁移脚本可重放测试（空库 → migrate → smoke，阶段 9/12 的技能）
main 验证：集成测试用真实迁移后的 schema
部署 job：
  1. 先跑迁移（独立 step/job，失败即中止，不部署代码）
  2. 再部署代码
  3. 健康验证
```

要点：

- **迁移先测试再应用**：CI 里对空库跑一遍迁移 + smoke，证明可重放（阶段 9 通过标准）；
- **迁移失败不部署**：迁移 job 失败 → deploy job 不跑（needs 语义）；
- **迁移要幂等/可重放**（幂等：重复执行结果相同，不会跑两遍就加两次列）：drizzle-kit/supabase 的迁移历史表保证不重复执行（阶段 8/9）；
- 破坏性迁移按 10.2 拆批。

## 10.4 回滚：可执行的流程，不是口号

本教程的回滚设计建立在两个事实上：**镜像 tag = commit sha**（旧版本永远在 GHCR）、**迁移兼容**（旧代码能跑在新 schema 上）。

回滚 runbook（操作手册，写进仓库 `docs/runbook.md`）：

```markdown
## 回滚到上一个稳定版本

1. 确认上一个稳定 sha：git log / 上次成功的 Deploy run
2. Actions → Deploy → Run workflow → image_tag 填该 sha
   （build-and-push 会复用/重推该 tag，deploy 部署它）
3. 观察健康验证 step 通过
4. 若本次发布含破坏性迁移（不应该，见 10.2）：
   - 优先「前滚修复」而不是回滚 schema
   - 必须回滚 schema 时：用备份恢复（阶段 8 第 13 章），并评估数据丢失窗口
5. 在事故记录里写：症状、影响、根因、修复、预防（阶段 17 的复盘模板）
```

**代码回滚容易，数据回滚难**——所以 10.2 的兼容策略才是真正的回滚保障：旧代码能跑，回滚才成立。

## 10.5 常见坑

| 现象                 | 原因                  | 解决                               |
| -------------------- | --------------------- | ---------------------------------- |
| 部署后旧实例报错     | 破坏性迁移与部署同批  | expand-migrate-contract 拆批       |
| 迁移跑了一半失败     | 迁移非事务/不可重放   | 事务包裹 + 迁移历史表；CI 先测     |
| 回滚后服务仍坏       | schema 已不兼容旧代码 | 前滚修复；平时守住兼容策略         |
| 不知道线上是哪个版本 | 没有发布标识          | tag=sha + /health 返回版本（可选） |
| 回滚靠口头指挥       | 没有 runbook          | 10.4 写进仓库并演练                |
