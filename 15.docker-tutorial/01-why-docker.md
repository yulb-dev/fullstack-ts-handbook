# 第 1 章：Docker 是什么

> 本章目标：在敲任何命令之前，先彻底搞懂四个最基本的问题——Docker 是什么、容器是什么、镜像是什么、为什么需要它。本章假设你**从没听说过 Docker**，用大白话和类比把地基打牢。
>
> 学完本章你能：用一句话向别人解释 Docker；分清「镜像」和「容器」；说出 Docker 帮你解决的三类问题。这些是后面所有章节的前提。

---

## 1.1 一句话：Docker 是什么

**Docker 是一个「把应用和它运行所需的一切打包在一起，让它在任何机器上都一致地运行」的工具。**

就这一句。先别管细节，记住这个画面：

> 你写了一个应用。它能不能跑，取决于很多东西——Node 的版本、装了哪些库、操作系统、配置、数据库……Docker 让你把「应用 + 这一切」装进一个标准箱子，搬到哪台机器都能原样跑起来。

### 集装箱类比

在集装箱发明之前，货物形状各异： sacks、木桶、钢卷……装卸靠人力，慢、易损、换运输工具就麻烦。集装箱把货物装进**标准尺寸的铁箱**，于是轮船、火车、卡车都能运同一箱货，吊装即走。

Docker 做的是同一件事，只不过装的是**软件**：

| 集装箱世界       | Docker 世界              |
| ---------------- | ------------------------ |
| 标准铁箱         | 容器（container）        |
| 箱子里的货物     | 你的应用 + 运行环境      |
| 轮船/火车/卡车   | 你的电脑/同事电脑/服务器 |
| 装箱的规格说明书 | Dockerfile               |

「软件集装箱」这个比喻，就是 Docker 名字里 dock（码头）的由来。

## 1.2 容器到底是什么（最重要的概念）

新手最容易误解的一点：**容器不是一台新电脑，也不是虚拟机。**

**容器就是你电脑上的一个普通进程，只是被 Docker「圈」了起来。** 圈起来之后：

- 它看不到别的进程（以为自己独占一台机器）；
- 它有自己的文件系统视图（一个隔离的目录树）；
- 它有自己的网络（自己的网卡和端口）。

但它**和你的电脑共享同一个操作系统内核**——没有多跑一个操作系统。所以容器极轻：启动一个容器 ≈ 启动一个进程，秒级甚至毫秒级。

### 公寓房间类比

把你的电脑想象成一栋公寓楼：

- **整栋楼** = 你的操作系统（共享地基、水电 = 内核）；
- **一个房间** = 一个容器：有自己的门锁、家具、空间，住户之间互不打扰；
- **房间里的住户** = 容器里运行的进程（比如你的 Fastify 服务）。

房间再隔离，也还是这栋楼的一部分（共享内核）——这就是容器和虚拟机的本质区别（1.6 节细说）。

> 现在你只需要记住：**容器 = 被隔离起来的进程**。后面所有命令，都是在「创建/启动/停止/删除这些被隔离的进程」。

## 1.3 镜像：容器的「模板」

容器从哪来？从一个叫**镜像（image）**的东西创建出来。

**镜像是一个只读的「打包好的快照」**，里面已经装好了：应用代码 + 运行时（如 Node 24）+ 所有依赖库 + 启动命令。它是一个静态文件，不会自己运行。

**容器 = 镜像 + 一层可写空间 + 运行起来的进程。**

### 蛋糕模具类比

- **镜像** = 蛋糕模具（或菜谱）：定义了「蛋糕长什么样」，本身不能吃；
- **容器** = 按模具烤出来的一个蛋糕：是真实存在、能吃的实例；
- 一个模具可以烤很多蛋糕 → **一个镜像可以启动很多个容器**，彼此独立。

镜像是只读的：你烤坏了一个蛋糕（容器里改坏了东西），模具（镜像）毫发无损，再烤一个就行。这就是为什么容器可以「用完即毁、随时重建」。

> 镜像还有一个重要特性：它是**分层**叠起来的（像千层蛋糕）。这决定了构建速度和体积，第 3、5 章会专门讲。现在先有个印象即可。

## 1.4 为什么需要它：一个最简单的例子

假设你写了一个 Node 应用，它需要 Node 24、几个 npm 库、一个 Postgres 数据库。

**没有 Docker 时**，换一台电脑要跑起来，你得：

```
1. 装 Node……版本装成了 20，应用用了 24 的 API，报错
2. 装依赖……忘了用 lockfile，装出的版本和你本地不一样
3. 装 Postgres……装包、建用户、配权限，折腾半小时
4. 配环境变量……漏了一个，启动失败
```

每一步都可能出错，而且每台机器都要重来一遍。这就是著名的「**在我机器上能跑啊**」——因为环境没被打包，全靠每台机器手动凑。

**有 Docker 时**：

```
把「Node 24 + 依赖 + 你的代码 + 启动命令」打成一个镜像（一次）
→ 任何装了 Docker 的机器：docker run 这个镜像 → 跑起来了，环境完全一致
数据库也是一行 docker run postgres:18，不用手动装
```

环境本身变成了「可以打包、可以分发、可以版本化」的东西。**「在我机器上能跑」升级成「在任何机器上都能跑」**——这就是 Docker 最核心的价值。

## 1.5 Docker 帮你做的三件事

| 动作            | 命令关键词                      | 解决什么                                         |
| --------------- | ------------------------------- | ------------------------------------------------ |
| **打包**        | `docker build`                  | 把应用+环境做成镜像                              |
| **分发**        | `docker push/pull`              | 把镜像传到仓库（registry），别人拉下来就能用     |
| **运行 / 编排** | `docker run` / `docker compose` | 跑单个容器，或一键起一组容器（应用+数据库+前端） |

对一个全栈工程师，具体收益是：

- **本地开发**：一行命令起 Postgres/Redis，不用在本机装一堆服务；
- **团队协作**：新人 clone 仓库后一条命令搭好整个环境，不用照着文档装一下午；
- **部署**：线上跑的就是你本地验证过的那个镜像，不再有「环境差异」事故。

## 1.6 Docker 不是什么（边界，避免误解）

- **不是虚拟机**：虚拟机跑一整个独立操作系统（重、分钟级启动）；容器共享内核、只隔离进程（轻、秒级）。需要跑不同操作系统或强隔离时才用虚拟机。
- **不是万能部署平台**：单机/小集群用 Docker + Compose 足够；大规模编排（成百上千容器、自动扩缩容）通常用 Kubernetes。本教程聚焦前者。
- **不自动保证安全**：Docker 给你隔离，但「非 root 运行、秘密不进镜像、健康检查」要你自己配（第 6、8、9 章）。**「镜像能跑」≠「生产可用」**。

## 1.7 术语小词典（先混个脸熟）

后面章节会反复用到这些词，现在先建立印象，不懂没关系，用到时会再讲：

| 术语           | 一句话解释                             |
| -------------- | -------------------------------------- |
| Docker         | 打包并运行「软件集装箱」的工具         |
| 容器 container | 被隔离起来的进程（运行实例）           |
| 镜像 image     | 只读的打包模板，容器从它创建           |
| Dockerfile     | 构建镜像的「配方」文本文件             |
| registry       | 存放/分发镜像的仓库（如 Docker Hub）   |
| 卷 volume      | 容器外的持久化存储（容器删了数据还在） |
| 网络 network   | 让多个容器互相通信的虚拟网络           |
| Compose        | 用一份 YAML 一键编排多个容器的工具     |

## 1.8 本教程怎么学

贯穿项目是 **Workboard**（一个任务协作应用，本系列毕业项目的骨架）。我们会把它的前端和后端真正装进容器。路径是：

```
搞懂概念（本章）→ 装好 Docker、跑第一个容器（第 2 章）→ 深入镜像/容器/层（第 3 章）
→ 自己写 Dockerfile（第 4~6 章）→ 网络/数据/配置/信号（第 7~9 章）
→ Compose 一键起全栈（第 10 章）→ 前端发布与维护（第 11~12 章）
```

每章都有可运行的命令、常见坑表格和验收清单。**第 2 章你就需要动手了**——本章的概念会在动手中变扎实。

## 1.9 常见误区

| 误区                          | 正确认知                                       |
| ----------------------------- | ---------------------------------------------- |
| 容器 = 一台新电脑/虚拟机      | 容器是被隔离的进程，共享宿主内核（1.2、1.6）   |
| 镜像和容器是一回事            | 镜像是只读模板，容器是运行实例（模具 vs 蛋糕） |
| 装了 Docker 就自动安全/可生产 | 还要非 root、秘密管理、健康检查（后续章节）    |
| 容器里改的东西会永久保存      | 容器可写层随容器删除而消失；持久化要用卷       |
