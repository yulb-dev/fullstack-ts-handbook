> 本章目标：**用 `createBrowserRouter` + `RouterProvider` 搭出「有层级」的路由系统**，彻底搞懂嵌套路由、layout route、index route、动态参数、splat。

## 2.1 Route Object：路由的「说明书」

在 Data Mode 里，路由不是 JSX，而是一个个**普通 JS 对象（Route Object）**，组成的数组交给 `createBrowserRouter`：

```tsx
import { createBrowserRouter } from "react-router";

const router = createBrowserRouter([
  { path: "/", Component: Home },
  { path: "/about", Component: About },
]);
```

一个 Route Object 上可以写的常用字段（本章先认识，后续章节逐个深入）：

| 字段 | 作用 | 详见 |
| --- | --- | --- |
| `path` | URL 匹配模式，支持 `:param`、`?` 可选、`*` splat | 本章 |
| `Component` | 匹配时渲染的组件 | 本章 |
| `children` | 子路由数组（嵌套） | 本章 |
| `index` | 标记为「索引路由」，在父路径处渲染 | 本章 |
| `loader` | 进入路由前加载数据 | 第 3 章 |
| `action` | 处理数据变更（表单提交） | 第 4 章 |
| `ErrorBoundary` | 路由级错误边界 | 第 6 章 |
| `lazy` | 懒加载路由定义（代码拆分） | 第 8 章 |
| `handle` | 附加任意元数据，配合 `useMatches`（如面包屑） | 第 10 章 |
| `shouldRevalidate` | 精细控制 loader 重新校验 | 第 5 章 |

> 💡 把 Route Object 想象成「一页说明书」：它同时告诉路由器「这个 URL 长什么样」「进来前要不要加载数据」「用哪个组件画」「出错了找谁」「要不要拆包」。所有路由相关信息**集中在一处**，这正是 Data Mode 相比声明式更易维护的原因。

## 2.2 嵌套路由：URL 的层级 = 组件的层级

嵌套路由通过 `children` 表达。**父路由的 path 会自动拼接到子路由前面**。

```tsx
createBrowserRouter([
  {
    path: "/dashboard",
    Component: Dashboard,
    children: [
      { index: true, Component: Home },        // 匹配 /dashboard
      { path: "settings", Component: Settings } // 匹配 /dashboard/settings
    ],
  },
]);
```

注意子路由的 `path` 是 **相对** 的：写 `"settings"` 而不是 `"/dashboard/settings"`，React Router 自动补全父级前缀。

### `<Outlet/>`：子路由的「插座」

嵌套的**视觉体现**靠 `<Outlet/>`。父组件在哪个位置放 `<Outlet/>`，匹配到的子路由组件就渲染在那里。

```tsx filename=src/routes/dashboard.tsx
import { Outlet } from "react-router";

export default function Dashboard() {
  return (
    <div className="dashboard">
      <aside>侧边栏导航</aside>
      <section>
        {/* 这里会渲染 Home 或 Settings，取决于当前 URL */}
        <Outlet />
      </section>
    </div>
  );
}
```

💡 **心智模型**：父组件是「画框」，`<Outlet/>` 是画框里的「照片位」。URL 变化时，只有「照片」被换掉，「画框」（布局、侧边栏、顶部导航）**保持不动、不会重新挂载**。这就是嵌套路由能做「布局不闪烁、局部刷新」的根本原因。

🧪 **动手实践**：把上一章的 `router.tsx` 改成带布局的嵌套结构。

```tsx filename=src/routes/root.tsx
import { Outlet, Link } from "react-router";

export default function Root() {
  return (
    <div>
      <header style={{ borderBottom: "1px solid #ccc", padding: 12 }}>
        <nav style={{ display: "flex", gap: 16 }}>
          <Link to="/">首页</Link>
          <Link to="/concerts">全部演唱会</Link>
          <Link to="/about">关于</Link>
        </nav>
      </header>

      {/* 子路由渲染处 */}
      <Outlet />

      <footer style={{ padding: 12, color: "#888" }}>
        © 2026 Concert Hub
      </footer>
    </div>
  );
}
```

> `<Link>` 是 React Router 的导航组件，点击时**不刷新整页**，只切换路由。第 7 章会深入 `Link` / `NavLink` 的区别与用法。

## 2.3 三种「不带完整 path」的特殊路由

这是新手最容易混的地方。请务必分清下面三种：

### (A) Layout Route（布局路由）：**有组件，无 path**

只提供一个「包裹用的布局组件」，**不往 URL 里加任何段**。它的 children 直接挂在父级 URL 下。

```tsx
createBrowserRouter([
  {
    // 注意：没有 path，只有 Component —— 这就是 layout route
    Component: MarketingLayout,
    children: [
      { index: true, Component: Home },      // 渲染在 "/"
      { path: "contact", Component: Contact } // 渲染在 "/contact"
    ],
  },
]);
```

用途：给一组页面套上共享的头部/背景/容器，但**不影响它们的 URL**。

### (B) Index Route（索引路由）：**`index: true`，无 path**

在**父路由的 URL 上**渲染的「默认子页面」。

```tsx
createBrowserRouter([
  { index: true, Component: Home }, // 渲染在 "/"
  {
    path: "/dashboard",
    Component: Dashboard,
    children: [
      { index: true, Component: DashboardHome },        // 渲染在 "/dashboard"
      { path: "settings", Component: DashboardSettings } // 渲染在 "/dashboard/settings"
    ],
  },
]);
```

💡 当用户访问 `/dashboard`（正好停在父路由，没有更深的子路径）时，父组件 `<Outlet/>` 里该渲染谁？答案就是 `index` 路由。它像「文件夹的默认首页（index.html）」。

> ⚠️ **index 路由不能有 children**。它本身就是叶子。

### (C) Prefix Route（前缀路由）：**有 path，无组件**

只为了给一组路由加一个**公共 URL 前缀**，但**不引入任何布局组件**。

```tsx
createBrowserRouter([
  {
    path: "/projects", // 只有 path，没有 Component
    children: [
      { index: true, Component: ProjectsHome },   // /projects
      { path: ":pid", Component: Project },        // /projects/:pid
      { path: ":pid/edit", Component: EditProject } // /projects/:pid/edit
    ],
  },
]);
```

它创建了 `/projects`、`/projects/:pid`、`/projects/:pid/edit` 三个 URL，但 `/projects` 段本身**不渲染任何自己的组件**（子路由直接渲染到更上层的 `<Outlet/>`）。

### 一张表分清三者

| 类型 | 有 `path`? | 有 `Component`? | 往 URL 加段? | 用途 |
| --- | :---: | :---: | :---: | --- |
| 普通嵌套路由 | ✅ | ✅ | ✅ | 既加 URL 段又渲染布局 |
| **Layout Route** | ❌ | ✅ | ❌ | 只套布局，不改 URL |
| **Index Route** | ❌（`index:true`） | ✅ | ❌ | 父 URL 上的默认页 |
| **Prefix Route** | ✅ | ❌ | ✅ | 只加 URL 前缀，不渲染布局 |

## 2.4 动态参数：`:id` 与 `useParams`

URL 里以 `:` 开头的段是**动态段**，匹配时会把该段的值解析出来，放进 `params`。

```tsx
createBrowserRouter([
  {
    path: "concerts/:city",
    Component: ConcertsCity,
    loader: ({ params }) => {
      // loader 里能拿到 params.city（第 3 章细讲）
      return getConcertsByCity(params.city);
    },
  },
]);
```

```tsx filename=src/routes/concerts-city.tsx
import { useParams } from "react-router";

export default function ConcertsCity() {
  const { city } = useParams(); // 组件里用 useParams 读取
  return <h1>{city} 的演唱会</h1>;
}
```

访问 `/concerts/chicago`，`params.city === "chicago"`。

**可以有多个动态段：**

```tsx
{ path: "c/:categoryId/p/:productId" } // /c/rock/p/123
// params = { categoryId: "rock", productId: "123" }
```

### 可选段：`?`

在段末尾加 `?` 让它变成可选：

```tsx
{ path: ":lang?/categories" }   // 匹配 /categories 和 /en/categories
{ path: "users/:userId/edit?" } // 匹配 /users/1 和 /users/1/edit
```

### Splat / Catchall：`*`

以 `/*` 结尾的路径会匹配后面的**任意字符（包括 `/`）**，常用于文件浏览器、404 兜底。匹配到的剩余部分放在 `params["*"]`。

```tsx
{
  path: "files/*",
  loader: ({ params }) => {
    params["*"]; // files/ 之后剩余的全部 URL
  },
}
```

```tsx
// 想解构出来用，需要重命名（* 不是合法标识符）
const { "*": splat } = useParams();
// 访问 /files/docs/2026/report.pdf → splat === "docs/2026/report.pdf"
```

> 💡 **`*` 兜底 404**：在路由表最后放一条 `{ path: "*", Component: NotFound }`，就能捕获所有未匹配到的 URL。第 6 章讲错误处理时会给出更专业的 404 方案（`throw data(..., {status:404})`）。

## 2.5 路径匹配与「相对链接」

React Router 用一套**打分排序（ranking）**算法决定「哪个路由最匹配当前 URL」——**越具体的路径优先级越高**，所以你通常不用操心书写顺序。比如同时存在 `concerts/:city` 和 `concerts/trending`，访问 `/concerts/trending` 会优先匹配更具体的**静态段** `trending`，而不是把 `trending` 当成 `:city`。

### `<Link to>` 的相对与绝对

- 以 `/` 开头 → **绝对路径**，从根算起：`<Link to="/concerts/chicago">`。
- 不以 `/` 开头 → **相对当前路由**：在 `concerts` 路由下写 `<Link to="chicago">` 会解析成 `/concerts/chicago`。
- `..` → 向上一级。

```tsx
// 在 /concerts 页面里
<Link to="trending">热门</Link>       // → /concerts/trending
<Link to="../about">关于</Link>        // → /about
<Link to="/about">关于（绝对）</Link>   // → /about
```

> ⚠️ 相对链接是相对**路由层级**，不是相对当前 URL 字符串。多数场景推荐**用绝对路径**（以 `/` 开头），可读性最好、最不易出错；只有做可复用组件时才用相对路径。

## 2.6 把整棵树搭出来（本教程的目标结构）

现在把上面的知识拼成 Concert Hub 的完整路由树：

```tsx filename=src/router.tsx
import { createBrowserRouter } from "react-router";

import Root from "./routes/root";
import Home from "./routes/home";
import About from "./routes/about";
import ConcertsLayout from "./routes/concerts/layout";
import ConcertsIndex from "./routes/concerts/index";
import ConcertsCity from "./routes/concerts/city";
import ConcertDetail from "./routes/concerts/detail";
import NotFound from "./routes/not-found";

export const router = createBrowserRouter([
  {
    path: "/",
    Component: Root, // 全局布局（header/footer + Outlet）
    children: [
      { index: true, Component: Home },          // "/"
      { path: "about", Component: About },        // "/about"
      {
        path: "concerts",
        Component: ConcertsLayout, // 区块布局（左侧城市列表 + Outlet）
        children: [
          { index: true, Component: ConcertsIndex }, // "/concerts"
          { path: "trending", Component: ConcertsCity }, // 演示静态段优先
          { path: ":city", Component: ConcertsCity },    // "/concerts/:city"
          { path: ":city/:concertId", Component: ConcertDetail }, // 详情
        ],
      },
      { path: "*", Component: NotFound }, // 兜底 404
    ],
  },
]);
```

对应的 URL 与组件层级：

```
/                         → Root > Home
/about                    → Root > About
/concerts                 → Root > ConcertsLayout > ConcertsIndex
/concerts/trending        → Root > ConcertsLayout > ConcertsCity   （静态段优先于 :city）
/concerts/chicago         → Root > ConcertsLayout > ConcertsCity   （params.city = "chicago"）
/concerts/chicago/3       → Root > ConcertsLayout > ConcertDetail  （params.city, params.concertId）
/whatever-not-matched     → Root > NotFound
```

每一层组件都在自己的位置放 `<Outlet/>`，子路由就被「插」进去：

```tsx filename=src/routes/concerts/layout.tsx
import { Outlet, Link } from "react-router";

export default function ConcertsLayout() {
  return (
    <div style={{ display: "flex", gap: 24, padding: 16 }}>
      <aside style={{ width: 180 }}>
        <h2>城市</h2>
        <ul>
          <li><Link to="/concerts/salt-lake-city">Salt Lake City</Link></li>
          <li><Link to="/concerts/chicago">Chicago</Link></li>
        </ul>
      </aside>

      {/* 匹配到的 concerts 子路由渲染在这里 */}
      <div style={{ flex: 1 }}>
        <Outlet />
      </div>
    </div>
  );
}
```

💡 注意 `ConcertsLayout` 只在**首次进入 `/concerts/*`** 时挂载。之后在 `/concerts/chicago` 和 `/concerts/trending` 之间切换时，`ConcertsLayout`（左侧城市列表）**不会重新挂载、不会闪烁**，只有右侧 `<Outlet/>` 里的内容在换。这就是嵌套布局带来的体验优势。

## 2.7 关于 `RouterProvider` 与 `createBrowserRouter` 的补充

- `createBrowserRouter(routes, opts?)`：接收路由对象数组，返回一个 **router 实例**。可传第二参数配置，如 `basename`（部署在子路径时）、`future`（提前开启未来行为）等。
- `<RouterProvider router={router} />`：把 router 实例接入 React 树并渲染。
- 📌 **`createMemoryRouter`**：在非浏览器环境（如 React Native、单元测试、SSR）里，用 `createMemoryRouter` 代替 `createBrowserRouter`——它的路由状态存在内存里而非浏览器 history。第 9 章测试会用到类似思路（`createRoutesStub`）。
- 📌 **`createRoutesFromElements`**：如果你就是喜欢用 JSX `<Route>` 写，但又要 Data Mode 的能力，可以用它把 JSX 转成路由对象数组：

```tsx
import { createBrowserRouter, createRoutesFromElements, Route } from "react-router";

const router = createBrowserRouter(
  createRoutesFromElements(
    <Route path="/" Component={Root}>
      <Route index Component={Home} />
      <Route path="concerts" Component={ConcertsLayout}>
        <Route index Component={ConcertsIndex} />
        <Route path=":city" Component={ConcertsCity} />
      </Route>
    </Route>
  )
);
```

> ⚠️ 两种写法能力完全等价。**对象数组写法**更贴近 Data Mode「配置在 React 之外」的理念，也更方便做 `lazy` 拆分，本教程后续统一用它。

## 🔧 常见坑 / 排错

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 子页面没渲染出来 | 父组件忘了放 `<Outlet/>` | 在父组件想显示子内容的位置加 `<Outlet/>` |
| `/dashboard` 空白 | 有 `path:"dashboard"` 的父路由但没配 `index` 子路由 | 加 `{ index:true, Component: ... }` |
| 子路由 path 写成 `/settings` 结果匹配不到 | 子路由 path 前多了 `/` 变成绝对路径 | 子路由用相对 path：`"settings"` |
| `useParams()` 拿到 `undefined` | 组件不在带该动态段的路由下 | 确认组件确实匹配到含 `:param` 的路由 |
| 想解构 splat 报语法错误 | `const { * } = useParams()` 中 `*` 非法 | 用 `const { "*": splat } = useParams()` |
| `/concerts/trending` 被 `:city` 吃掉了 | 误以为顺序决定优先级 | React Router 按「具体度」打分，静态段天然优先；把 `trending` 与 `:city` 平级并列即可 |
