# 第 1 章 · 模式选型与环境搭建

> 本章目标：**搞清楚 React Router 的三种「模式」，理解我们为什么选 Data Mode，并跑起第一个页面。**
> 对应验收项：①（模式选型）
> 预计用时：30–45 分钟

---

## 1.1 先建立一个心智模型：路由到底管什么？

很多新手把「路由」理解成「URL 变了就换一个组件显示」。这只是路由最表层的功能。

一个**成熟的路由系统**其实要同时管理四件事：

1. **页面层级（Hierarchy）**：URL `/concerts/salt-lake-city` 天然是一棵树——先匹配「演唱会列表区」，再匹配「某城市」。页面也应该能嵌套、共享布局。
2. **URL ↔ 状态（State in URL）**：筛选条件、排序、分页、当前选中项……这些「可分享、可前进后退」的状态，应该由 URL 表达，而不是藏在组件内存里。
3. **数据的加载与提交（Data）**：进入一个页面**之前**要把数据准备好；用户提交表单**之后**要让相关数据自动刷新。
4. **导航状态（Navigation state）**：现在是不是正在加载？是不是正在提交？表单提交到哪一步了？——这些「pending」状态决定了 loading 转圈、按钮禁用、乐观更新等体验。

💡 **传统做法的痛点**：在老式的 React SPA 里，第 1、2 件事由路由管，第 3、4 件事却要你在每个组件里手写 `useEffect` + `useState` + `loading` 标志位。结果是：数据加载逻辑散落各处、竞态（race condition）难处理、loading 状态各写各的、代码难以复用和测试。

React Router 的 **Data Mode** 就是为了解决这个割裂：**把「数据」和「导航状态」也变成路由的一等公民**，用 `loader`（加载）、`action`（提交）、`useNavigation`（导航状态）统一管理。

带着这个认知，我们来看三种模式。

---

## 1.2 三种模式：Declarative / Data / Framework

React Router 官方把自己称为「多策略路由器（multi-strategy router）」。同一个库，有**三种使用方式（模式）**。最关键的一句话：

> 💡 **三种模式的特性是「递增」的（additive）：Declarative ⊂ Data ⊂ Framework。**
> 从 Declarative 到 Data 再到 Framework，只是**不断叠加更多功能**，代价是你**交给框架的架构控制权越来越多**。
> 所以选型的问题不是「哪个更强」，而是「**我想自己掌控多少、想让路由替我做多少**」。

模式的区别，体现在你用的「顶层 API」不同。

### 模式一：Declarative Mode（声明式）

最基础的模式。提供：URL ↔ 组件的匹配、应用内导航、active 状态。核心 API 是 `<BrowserRouter>` + `<Routes>` + `<Route>`。

```tsx
import { BrowserRouter, Routes, Route } from "react-router";

ReactDOM.createRoot(root).render(
  <BrowserRouter>
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
    </Routes>
  </BrowserRouter>,
);
```

- ✅ 提供：`<Link>`、`<NavLink>`、`useNavigate`、`useLocation`、`useParams`、`<Outlet/>`、`<Navigate>` 等。
- ❌ **不提供**：`loader`、`action`、`useFetcher`、`useNavigation`、`useLoaderData`、路由级错误边界等「数据能力」。
- 适用：**只想用最简单的路由**；数据层自己有方案（比如 local-first、后台同步、React Query/TanStack Query 自带 pending 抽象）；从很老的 React Router 版本迁移且满意现状。

### 模式二：Data Mode（数据模式）—— 本教程主角

把**路由配置从 React 渲染里搬出来**，变成一个「路由对象数组」，交给 `createBrowserRouter` 创建 router，再用 `<RouterProvider>` 渲染。

```tsx
import { createBrowserRouter, RouterProvider } from "react-router";

let router = createBrowserRouter([
  {
    path: "/",
    Component: Root,
    loader: loadRootData, // ← 进入路由前加载数据
  },
]);

ReactDOM.createRoot(root).render(<RouterProvider router={router} />);
```

- ✅ 在 Declarative 全部能力之上，**新增**：`loader`、`action`、`useLoaderData`、`useActionData`、`useNavigation`、`useFetcher`、`useSubmit`、`<Form>`、路由级 `ErrorBoundary`/`errorElement`、`redirect`、`data`、`shouldRevalidate`、`createRoutesStub`（测试）等。
- 代价：路由配置写法与声明式不同（对象数组，不是 JSX `<Route>`）；需要你**自己搭打包器和服务端**（React Router 不管你的构建）。
- 适用：**想要 loader/action/pending 这些数据能力，但又想自己掌控打包、数据层与服务端抽象**；或者你在 v6.4 就用过 data router 且满意。

> 💡 **为什么本教程选 Data Mode？**
> 因为绝大多数「中后台系统 / 内容型网站 / 管理面板」类 SPA 的痛点，恰恰是**数据加载与提交的状态管理**，而这正是 Data Mode 的强项。同时，Data Mode **不绑定任何构建工具或服务端**——你用 Vite、Webpack、Rspack 都行，部署到静态服务器、Node、边缘运行时都行。它给了你「数据能力」与「架构自由」的最佳平衡点。等你确实需要 SSR / 类型安全路由 / 自动代码拆分时，再平滑升级到 Framework Mode 即可（概念完全一致）。

### 模式三：Framework Mode（框架模式）

在 Data Mode 之上，用一个 **Vite 插件（`@react-router/dev`）** 把「整个 React Router 体验」封装起来：

```ts filename=routes.ts
import { index, route } from "@react-router/dev/routes";

export default [
  index("./home.tsx"),
  route("products/:pid", "./product.tsx"),
];
```

- ✅ 在 Data Mode 全部能力之上，**新增**：类型安全的 `href`、类型安全的 Route Module API、**智能代码拆分**、SPA / SSR / 静态渲染（SSG）多种策略、`<Link prefetch>`、`Meta`/`Links`/`Scripts` 等。
- 代价：必须用它的 Vite 插件与约定（文件即路由、Route Module API），架构控制权交给框架更多。
- 适用：**新手还没形成偏好**、正在对比 Next.js/SolidStart/SvelteKit/Astro/TanStack Start、可能想要 SSR、或从 Next.js 迁移。

### 三模式对照速记表

| 能力 | Declarative | Data | Framework |
| --- | :---: | :---: | :---: |
| `<Link>` `<NavLink>` `useNavigate` `useLocation` `useParams` `<Outlet/>` | ✅ | ✅ | ✅ |
| `<Form>` `useLoaderData` `useActionData` | ❌ | ✅ | ✅ |
| `loader` / `action` / `redirect` / `data` | ❌ | ✅ | ✅ |
| `useNavigation` / `useFetcher` / `useSubmit` / `useRevalidator` | ❌ | ✅ | ✅ |
| 路由级 `ErrorBoundary` / `errorElement` / `useRouteError` | ❌ | ✅ | ✅ |
| `createRoutesStub`（测试） | ❌ | ✅ | ✅ |
| route `lazy`（手动代码拆分） | ❌ | ✅ | ✅ |
| 类型安全 `href` / 自动代码拆分 / SSR / SSG | ❌ | ❌ | ✅ |

> 📌 完整表格见官方 [Picking a Mode](https://reactrouter.com/start/modes)。记住结论即可：**Data Mode = Declarative 的全部 + 数据/导航状态能力，但不接管你的构建与服务端。**

## 1.3 环境搭建：创建项目

我们用 **Vite** 搭一个最小的 React + TypeScript 项目（你也可以用任意打包器，Data Mode 不挑）。

🧪 **动手实践**

```bash
# 1) 创建 Vite 项目（选 React + TypeScript）
npm create vite@latest concert-hub -- --template react-ts
cd concert-hub

# 2) 安装依赖
npm install

# 3) 安装 React Router v8（主包就是 react-router）
npm install react-router

# 4) 确认版本（应显示 8.x）
npm ls react-router
```

> ⚠️ **不要**再装 `react-router-dom`。v8 里它是**兼容层**，新项目统一从 `react-router` 导入即可。如果你误装了两个包，可能出现「两个 router 实例」导致的上下文错误。

> 📌 **React 版本**：`react-router@8.5` 要求 `react >= 19.2`。Vite 的 `react-ts` 模板当前默认已是 React 19，一般无需处理。若你的 `package.json` 里 React 还是 18，请执行 `npm install react@^19 react-dom@^19 @types/react@^19 @types/react-dom@^19`，或改用 `react-router@7`（概念完全相同）。

### 目录结构约定

本教程会逐步把项目组织成下面这样（现在只需先建好 `src/routes/` 目录）：

```
concert-hub/
├─ index.html
├─ package.json
├─ vite.config.ts
├─ tsconfig.json
└─ src/
   ├─ main.tsx          # 入口：创建 router 并渲染 RouterProvider
   ├─ router.tsx        # 路由表（createBrowserRouter 的数组）
   ├─ api.ts            # mock 数据层（带人工延迟，模拟真实网络）
   └─ routes/           # 每个页面/布局一个文件
      ├─ root.tsx
      ├─ home.tsx
      └─ ...
```

## 1.4 跑起第一个 Data Mode 页面

我们先用**最小的代码**把 Data Mode 的骨架跑通，验证环境 OK。后面章节会不断往里加东西。

🧪 **动手实践**

**第 1 步：写一个 mock 数据层 `src/api.ts`**

为了让「加载状态」看得见，我们给每个请求都加一点**人工延迟**，模拟真实网络。

```ts filename=src/api.ts
// 一个极简的内存数据层，模拟后端 API。
// 所有方法都带延迟，方便我们观察 loading / pending UI。

const delay = (ms: number) => new Promise((r) => setTimeout(r, ms));

export type Concert = {
  id: string;
  city: string;
  title: string;
  date: string; // ISO 日期字符串
};

let concerts: Concert[] = [
  { id: "1", city: "salt-lake-city", title: "The Folklore Sessions", date: "2026-11-02" },
  { id: "2", city: "salt-lake-city", title: "Neon Desert Live", date: "2026-11-18" },
  { id: "3", city: "chicago", title: "Windy City Rockfest", date: "2026-12-05" },
  { id: "4", city: "chicago", title: "Jazz by the Lake", date: "2026-12-20" },
];

export async function listConcerts(): Promise<Concert[]> {
  await delay(300);
  return concerts;
}
```

**第 2 步：写路由表 `src/router.tsx`**

```tsx filename=src/router.tsx
import { createBrowserRouter } from "react-router";
import { listConcerts } from "./api";
import type { Concert } from "./api";

// 首页组件：用 useLoaderData 读取 loader 返回的数据
import { useLoaderData } from "react-router";

function Home() {
  const { concerts } = useLoaderData() as { concerts: Concert[] };
  return (
    <main>
      <h1>Concert Hub 🎸</h1>
      <ul>
        {concerts.map((c) => (
          <li key={c.id}>
            {c.title} — {c.city}（{c.date}）
          </li>
        ))}
      </ul>
    </main>
  );
}

// loader：进入 "/" 路由【之前】运行，返回的数据供组件读取
async function homeLoader() {
  const concerts = await listConcerts();
  return { concerts };
}

export const router = createBrowserRouter([
  {
    path: "/",
    Component: Home,
    loader: homeLoader,
  },
]);
```

**第 3 步：在入口渲染 `src/main.tsx`**

```tsx filename=src/main.tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { RouterProvider } from "react-router";
import { router } from "./router";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>,
);
```

> ⚠️ **关键点：router 对象必须在 React 组件树之外创建一次**。
> 官方明确说明：data router「不应该被放进 React state」。你要在模块顶层 `createBrowserRouter(...)` 一次，然后把这个稳定的对象传给 `<RouterProvider>`。如果在组件渲染里创建 router，每次渲染都会重建路由与数据，导致无限加载和数据错乱。

**第 4 步：运行**

```bash
npm run dev
```

打开浏览器访问开发服务器地址（Vite 默认 `http://localhost:5173`）。你应该看到演唱会列表。

💡 注意观察：因为 loader 有 300ms 延迟，页面数据是「进入路由前」由 loader 拉取的。此刻你还没看到 loading 态——那是第 5 章的内容。但你要建立的核心认知是：

> **在 Data Mode 里，`Home` 组件被渲染时，`concerts` 数据【一定已经准备好了】。** 组件里不需要写 `useEffect` 去拉数据、不需要判断 `if (!data) return <Loading/>`。数据在路由层就被 loader 挡住了。这就是「数据即路由的一等公民」。

## 1.5 这一章的关键概念回顾

- 路由系统要同时管理：**页面层级、URL 状态、数据加载/提交、导航状态** 四件事。
- 三种模式 **递增**：Declarative（基础导航）→ Data（+ loader/action/pending/错误边界，但不接管构建）→ Framework（+ 类型安全/自动代码拆分/SSR，绑定 Vite 插件）。
- 我们选 **Data Mode**：因为它精准解决「数据与导航状态」的痛点，又保留了架构自由。
- Data Mode 骨架 = `createBrowserRouter(路由对象数组)` + `<RouterProvider router={router} />`。
- **router 在 React 之外创建一次**；loader 在组件渲染**之前**运行；组件用 `useLoaderData()` 读取。

## 🔧 常见坑 / 排错

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 报错 `useLoaderData may be used only in the context of a <Router>` | 用了 `<BrowserRouter>` 却调用了 Data Mode 的 hook | Data Mode 必须用 `<RouterProvider>`，不能用 `<BrowserRouter>` |
| 页面无限 loading / 数据反复刷新 | 在组件渲染函数里调用了 `createBrowserRouter` | 把 router 提到模块顶层，只创建一次 |
| 刷新页面 404（开发/部署时） | 服务器没有把未知路径回退到 `index.html` | Vite dev 已自动处理；部署到静态服务器需配置 SPA fallback（见第 10 章） |
| 同时装了 `react-router` 和 `react-router-dom` 出现诡异上下文错误 | 两个包各带一份运行时 | 卸载 `react-router-dom`，统一用 `react-router` |
| TS 报 React 版本不兼容 | `react-router@8` 要求 React ≥ 19.2 | 升级 React 到 19，或改用 `react-router@7` |

> 📌 **v7 用户**：若你用 `react-router@7`，本章所有代码原样可用，仅版本号不同。v7→v8 对 Data Mode 的 API（`createBrowserRouter`、`loader`、`action`、`useNavigation`、`useFetcher` 等）保持兼容；v8 主要新增了 `middleware` 等能力并深化类型安全，这些不影响本教程主线。
